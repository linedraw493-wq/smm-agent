# Решение — учёба идёт по делу, а не по часам

**Слово владельца 2026-08-25:** «Удали систему автоскроллинга в пн и чт, тулу
от неё, если она тупо анализирует данные.»

Задача `alya-trend-scan` стояла в планировщике на понедельник и четверг,
10:23. Удалена вместе с файлом её указаний. **Право учиться без владельца
остаётся** ([[2026-08-23-alya-avtonomnoe-obuchenie]]) — уходит только запуск
по часам.

## Почему это правильно, а не потеря

Сравнили две стопки разборов, ручную и автоматическую.

| | руками | автоматом 2026-08-24 |
|---|---|---|
| разборов | 24 | 4 |
| размер карточки | 5–8 КБ | 2.4 КБ |
| повторов уже разобранного | 0 | 2 из 4 |
| лог прогона | есть | не заведён, хотя инструкция требует |

Автоматический прогон качал те же ролики второй раз (`watch.py` не сверяет
номер ролика, а только имя папки) и оставлял карточки, где числа сняты, а
приём не назван. По правилу школы такая карточка **в счёт просмотров не
идёт** — то есть прогон производил работу, которая сама себя не засчитывает.

Плохо не смотреть. Плохо смотреть по часам, без вопроса, ради которого
смотришь.

## Инструмент остаётся

`tools/watch.py` **не удаляется**: руками он дал все 24 хороших разбора и
корпус чисел. Удалён запуск по расписанию, а не умение смотреть.

Хвост, который теперь стал важнее: **сверять скачанное по номеру ролика**, а
не по имени папки — [[../backlog]].

## Как учёба запускается теперь

- Фразой владельца: «поучись», «посмотри роликов», «разбери этого».
- Самой Алей по делу: перед новым выпуском · когда уперлась в вопрос «как это
  делают другие» · после правки владельца, повторившейся дважды
  ([[../operations/uchitsya]]).

Вход не меняется: `operations/uchitsya.md` и `operations/razvedka-trendov.md`,
запись — в `trends/`, в `craft/` по-прежнему нельзя.
