# run — что вышло

**Сделано 2026-08-26.** Две картинки из одного макета. Наружу ничего не ушло.

## Смена инструмента: не Pillow, а HTML

Карточка «Лидера» рисовалась кодом на Pillow. Здесь эталон владельца требует
скруглённых карточек, теней, контурных иконок и макета телефона — на Pillow это
неделя возни и хрупкий код. Взят другой путь: **макет пишется как обычная
веб-страница, снимок делает headless Chrome**.

```sh
chrome.exe --headless=new --disable-gpu --hide-scrollbars \
  --allow-file-access-from-files --force-device-scale-factor=1 \
  --window-size=1080,1920 --screenshot=out.png "file:///.../case.html"
```

Что это дало: точный размер кадра пикселями, иконки контуром через inline SVG,
шрифты — те же статические TTF из `assets/fonts` через `@font-face`.
`--force-device-scale-factor=1` обязателен: без него Chrome берёт масштаб
системы и кадр приезжает не 1080 шириной.

## Грабли

- **Первая редакция текста забракована владельцем: «непонятно, о чём текст».**
  Кадр был про нашу работу, а не про клиента и его дело. Разбор и правка —
  в `script.md` §Первая редакция. Правило вынесено в
  [[../../alya-vault/craft/marketing]].
- **Heredoc с HTML внутри `bash -c` рвётся.** Файл макета пишется инструментом
  записи файла, а не `cat <<'EOF'`.
- **Сторис нельзя рисовать во весь кадр.** Интерфейс Instagram лежит поверх:
  верх и низ съедаются. Отсюда два файла из одного макета, а не один.
  Ужимание сделано `transform: scale()` на всю страницу — макет один,
  расхождения между версиями не будет.
- **Пустота внизу кадра.** Первый прогон оставил ~350 px пустоты над подвалом:
  на глаз макет выглядел законченным, а кадр — нет. Правится не подгонкой
  одного отступа, а равномерным ростом всех: кегли, поля карточек, зазоры.
